# paper-system 演进路线图（v1.2.0 之后）

## Context

基于两轮只读审计（功能完整性 + 技术债量化）制定的演进计划。审计确认了几个**此前不知道的硬缺口**（部署后无人能改密码、每日备份只含 DB 不含论文文件、500 错误返回纯文本、session 无法吊销），加上之前已定但暂缓的事项，组织为按优先级分批的路线图。每批可独立提交、独立回滚。

## 审计发现摘要（证据已核实）

**功能硬缺口**：密码修改完全缺失（含 admin，部署后无人能改）；会话无法服务端吊销（cookie 30 天硬编码，登出只删 cookie）；无用户禁用/删除/重置密码；audit_log 表只写不读（全项目仅 1 处写入）；翻译导出/Markdown 下载后端存在但前端无入口；段落笔记是半成品（表在、API/UI 全无）；/api/usage 无 UI；大库无分页（LIMIT 500）；回收站无孤儿文件检测。

**技术债**：viewer.js 2729 行（149 个顶层函数、73 处 innerHTML 全量渲染、50 个松散 state 键、19% 篇幅是"恢复区"补丁带）；main.py 64 个端点零 APIRouter；无全局 exception handler（500 返回纯文本 "Internal Server Error"，前端只能显示 HTTP 500）；SSE 流中 validate/DB 写在 try 之外（可能中途断流）；CSP/XFO/ XCTO 安全头全无；登录限速内存态重启清零；**每日备份只含 DB，papers/ 文件目录完全不在备份内**（DB 快照引用的文件丢失即不可复原）；openPaper 一次 10-11 个请求（jobstate 重复拉 2 次）；SSE 事件每条触发 1-4 个请求放大；批量操作 N+1 串行；容器无内存限制。

---

## 第一批（P0）：数据安全 + 认证修补 —— 约 2-3 小时

必须尽快，都是小改动大风险项。

1. **备份补全 papers/ 文件**：`app/core/jobs.py:_daily_backup()` — DB 快照之外，将 `data/papers/` 打 tar（`papers-YYYY-MM-DD.tar.gz`，按 mtime 增量或直接全量，目录当前 28MB 很小），与 db-*.db 同批按 `retention.backup_keep` 轮转；轮转 glob 改为同时覆盖 `pre-audit-*.db`。
2. **密码修改**：`POST /api/password`（旧密码验证 + 新密码 argon2 哈希，复用 `auth.verify_password/hash_password`）；admin 可 `POST /api/admin/users/{id}/reset-password` 生成临时密码；设置页加"账号安全"卡片（`renderSettings`）。
3. **会话吊销**：users 表加 `token_ver INTEGER DEFAULT 0`（迁移 v12）；session 签名 payload 带 ver，校验时比对（`auth.parse_session`）；改密码/登出所有设备 → ver+1；设置页加"登出所有设备"按钮。同时把 30 天 max_age 收敛到单处（`auth.SESSION_MAX_AGE`）。
4. **全局错误处理**：main.py 注册 `@app.exception_handler(Exception)` → 返回 `{"detail":"服务器内部错误"}` JSON + `log.exception`；SSE gen() 里 validate/DB 写包进 try，失败发 `{"type":"error"}` 事件而非断流。
5. **安全响应头**：中间件统一加 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、基础 CSP（img-src self data: blob:、script-src self）。

**验证**：smoke-test.sh 增补 3 项（改密码→旧密码失效→新密码可用；登出所有设备→旧 cookie 401；500 返回 JSON）。审计脚本全绿。

## 第二批（P1）：多用户就绪 —— 约 3-4 小时

要给别人用之前必须补齐。

1. **用户管理**：users 表加 `disabled INTEGER DEFAULT 0`（迁移 v12 同批）；`POST /api/admin/users/{id}/disable|enable`、`DELETE /api/admin/users/{id}`（软删：disabled+清 session）；登录处校验 disabled；管理区 UI 加用户操作列。
2. **audit_log 真正启用**：登录失败/成功、删论文、改配额、改密码、禁用用户时写入；`GET /api/admin/audit?limit=100`；管理区加审计日志卡片。
3. **登录限速改进**：_fail_log 同时按 IP+用户名计数；加简单上限清理（防内存增长）。
4. **会话管理 UI**：后端补 `DELETE /api/chat/sessions/{id}`、`PATCH .../rename`；dock 加会话切换下拉（最近 20 条，显示标题/时间，可删/重命名）——呼应之前的分级设计。
5. **论文列表分页**：/api/papers 加 `page/page_size` 参数（保持兼容：不传 page 行为不变），前端侧栏加"加载更多"。

**验证**：smoke-test 增补（禁用用户→登录 403；审计日志有记录）；巡检脚本全绿。

## 第三批（P2）：功能补全 —— 约 3-4 小时

1. **导出中心**：文献信息卡加"导出"下拉——翻译 Markdown（后端已有 `/export/translation`，只缺入口）、解析 Markdown（`/markdown` 已有）、导读 Markdown（新增端点，复用 `_md_response`）、BibTeX 批量下载（新端点：多选论文 → 单 .bib 文件，复用 `copyCite` 的 BibTeX 模板）。
2. **导读改异步任务**：jobs.py 加 summary handler（复用现有 job 队列与进度 SSE），生成中显示进度、完成自动刷新；移除"约 20-60 秒"同步阻塞。
3. **段落笔记做删决策**（默认：删除——历史上你精简过段落批注，block_notes 表是残留；迁移 v12 DROP；若想保留则做 API+UI，工作量 +2 小时）。
4. **/api/usage 接入管理区**：token 用量表格（已有端点，加卡片渲染）。
5. **杂项**：回收站文案与 `retention.trash_days` 联动（前端从 /api/health 或 /api/me 取配置）；llm_calls 孤儿行随论文删除清理；`ps-pos-*` localStorage 在论文硬删时清除。

**验证**：导出文件内容抽查；导读任务在任务中心可见进度；巡检 + 冒烟全绿。

## 第四批（P3）：体验优化 —— 约 2-3 小时

1. **性能包**：openPaper 去重 jobstate（复用第一次结果）+ renderMeta 3 请求并行（Promise.all）；SSE 事件驱动的 refreshQueueBadge 加 3s 节流；批量删除/移入改批量端点（`POST /api/papers/batch-delete|batch-move`）；论文硬删时清 `ps-pos-*`。
2. **深色模式**：`[data-theme="dark"]` 覆盖 :root 变量（tint 地基已就绪）+ 顶栏切换按钮 + localStorage 记忆 + prefers-color-scheme 默认。
3. **CSS 清理**：删 4 个死选择器、补 `.col-arrow.closed` 旋转样式、合并 3 处重复的 `.pair.en.blk-title` 块。
4. **移动端问答**：≤880px 时 dock 改为全屏抽屉（底部输入固定），修复小屏阅读+问答切换。

**验证**：截图对比明暗两套主题；巡检 + 冒烟全绿。

## 独立排期（每项单独一轮，不并入上面）

- **结构重构**：viewer.js 拆模块 + 高频列表定向更新（73 处 innerHTML 中优先 renderPapers/renderContentView/renderQaUI 三处热点）；main.py 按 URL 前缀拆 APIRouter（审计已给出分组：papers 27 / admin 5 / chat 4 / collections 4 / jobs 4 / settings 3 / glossary 3 / queue 2）。
- **库级对比工作台**：等 dock 对比用出痛点后设计（核心问题：对比维度来源、报告持久化形态）。
- **异地备份**：`data/backups/` rsync 到第二块盘或远端（一次性 crontab 配置）。
- **翻译实测**：3 篇论文跑完整翻译，验证 token 计量与耗时。

## 执行顺序建议

第一批 → 第二批 →（睡觉醒来先看 P0 是否有异议）→ 第三批 → 第四批 → 独立排期逐项。每批一个 commit + tag 不动（下个版本节点 v1.3.0 在第二批完成后打）。
