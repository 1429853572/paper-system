## 系统一句话

自托管的多用户学术论文工作台：**PDF GPU 深度解析 → 双栏精读（双语/证据问答/个人标注）→ 表格→可用数据 → 文献订阅巡逻 → 批量综述（证据溯源）**，5 名真实用户使用中，95 篇论文 / 2.4 万解析块 / 635 张表格条目。

## 建议评估路径（30-45 分钟）

### 第一站：阅读 + 证据问答（10 分钟）——核心差异化

1. 登录后左侧点开任意论文（如 MetroGS）
2. 左 PDF 右原文，点右侧任意段落 → **PDF 自动跳页 + 高亮**
3. 选中正文一段 → 浮条（AI 解读 / 提问 / 翻译 / 高亮 / 批注 / 文献入库）→ 点「AI 解读」
4. 右栏提问任意内容 → 回答中蓝色 **[n] 引用可点击** → PDF 跳到源句闪烁
5. 试试「双语对照」「中文」视图切换

**请评估**：证据溯源机制对学术可信度的价值；划词标注的工作流合理性。

### 第二站：表格工作台（10 分钟）——数据提取

1. 顶栏「表格」→ KPI 统计带（93 篇论文 635 张表）
2. 任意卡片「对照」→ **左原始截图 / 右可编辑数据** 并排核验
3. 关闭 → 勾选 2+ 张卡片 → 批量条「聚合」→ 选模式下载 xlsx
4. 顶部「整理待办」按钮（LLM 批量整理，含防漏校验：行列不一致自动转人工）

**请评估**：表格数据提取的准确性与可核验性设计；对文献数据整理工作流的实际价值。

### 第三站：文献追踪（5 分钟）——订阅巡逻

1. 顶栏「追踪」→ 左栏订阅卡「巡逻」（等 10-20 秒）
2. 收件箱新条目：tier 分层徽章 / 中文摘要 / 期刊分区 / 被引数
3. 勾选「已收进」条目 → 批量条「发起综述」

**请评估**：订阅巡逻的工作流对文献跟踪的覆盖；与 Stork/Feedly 类产品的比较。

### 第四站：问答对比 + 综述（5 分钟）

1. 回答区「＋ 添加论文」→ 勾选第二篇 → 提问（多篇对比模式）
2. 文库管理勾选 2+ 篇论文 → 批量条「综述」→ 看费用预估与参数弹窗（可实际发起 quick 档）

### 第五站：管理后台（可选，当前账号已是管理员）

## 技术背景速览（架构师）

- **栈**：FastAPI + SQLite(WAL+FTS5) + MinerU 4.1.6(GPU) + xinference(BGE-M3) + Caddy + 原生 JS（无框架）
- **规模**：~2.3 万行（后端 158 路由/31 表/10 worker 线程 + 前端 15 分片）
- **性能**：500 篇模拟压测全部核心查询 ≤21ms（DB 非瓶颈，瓶颈在 LLM 吞吐）
- **可靠性**：每日双备份（DB+文件+SHA256 manifest）/ 10 worker 线程任务恢复 / 系统健康卡+告警邮件

## 重点征询（按优先级）

1. **上线把关**：当前架构（单机单进程 SQLite）在 5-20 用户场景下是否可放行？最该补的一项是什么？
2. **改进方向**：对照功能矩阵，你认为投入产出比最高的 3 项改进是什么？
3. **安全**：BYOK 模式下用户 LLM key 由系统 Fernet 加密存储——第三方托管用户凭据的风险边界？
4. **领域**：工作流覆盖有无重大缺口？术语与交互是否符合研究者心智模型？
5. **合规**：中文文献采集含滑块拟人化处理（自动失败即回落人工）——风险评价？
