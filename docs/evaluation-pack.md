## 0. 系统一句话

自托管的多用户学术论文工作台：**PDF 深度解析（GPU）→ 双栏精读（双语/证据问答/个人标注）→ 知识提取（表格→可用数据）→ 文献追踪（订阅巡逻）→ 批量综述（证据溯源）**，单机部署，5 名真实用户使用中。

## 3. 运行数据（2026-11-14 真实快照）

- 规模：95 篇论文 / 24,376 解析块 / 635 表格条目 / 3 订阅 / 5 用户 / 13GB 数据
- 解析成功率：97/97（0 失败）
- 性能（500 篇模拟压测）：全部核心查询 ≤21ms——DB 不是瓶颈，瓶颈在 LLM 吞吐
- 可靠性：容器 up 7 天（healthy）；每日双备份（DB+文件，SHA256 manifest）；磁盘 62%
- 代码量：后端 13.5K 行（158 路由/31 表/10 worker）+ 前端 9.4K 行（15 分片）；313 commits
- 测试：backend 94 / smoke 50 / permission 39 / jsdom×10 套 / e2e 走查资产；3 轮对抗审计

## 4. 5 分钟演示脚本（评估者可自行操作）

演示账号：`（部署时创建 member 角色账号，凭据交给评估者）`

1. **阅读**：左侧点开任意已解析论文 → 左 PDF 右原文 → 点右侧段落（PDF 跳页高亮）→ 划词选一段（浮条：AI 解读/提问/翻译/高亮/批注）→ 点「AI 解读」
2. **证据问答**：提问任意内容 → 回答中蓝色 [n] 引用 → 点击 → PDF 跳到源句闪烁
3. **表格**：顶栏「表格」→ 任意卡片「对照」（左原图右数据）→ 编辑一格保存 → 勾选 2 张 → 批量条「聚合」下载 xlsx
4. **追踪**：顶栏「追踪」→ 点订阅卡「巡逻」（10-20 秒）→ 收件箱出现新论文（tier 徽章/中文摘要）→ 勾选「发综述」
5. **任务**：顶栏「任务」→ 看 table_tidy/综述批次进度卡

## 5. 技术栈与代码导览（架构师视角）

```
app/
├── server/main.py        13526 行中的 ~5K：158 路由，薄层（校验→调 core→emit SSE）
├── core/
│   ├── jobs.py           调度器：10 worker 线程 + 任务表持久化 + SSE EventBus
│   ├── llm.py            LLM 统一网关（BYOK/池/预算闸/记账/退避）
│   ├── ingest.py         解析产物→blocks/chunks/FTS
│   ├── meta.py           五源元数据级联校准
│   ├── qa.py             证据检索问答（引用校验 PASS 才交付）
│   ├── synthesis.py      综述流水线（聚类分组比对）
│   ├── tracker.py        订阅巡逻（arXiv/OpenAlex 采集+去重+分层）
│   ├── tables.py         表格收割/网格化/LLM 整理/xlsx
│   ├── tracker_mail.py   全局 SMTP（日报/健康告警）
│   └── health.py         健康指标+阈值判定
├── webui/                15 分片原生 JS + styles.css（token 体系）
└── Dockerfile            唯一构建物（openpyxl 为唯一非必需依赖）
```

**专家抽查建议**（每处 5 分钟）：
1. `core/llm.py` ——预算闸是否可靠（多用户共享场景）
2. `server/main.py` 的 `_cache_policy` 中间件 + require 模式——权限模型是否完备
3. `core/tables.py` 的 `tidy_one` ——LLM 输出防漏校验的设计
4. `core/jobs.py` 的 `Scheduler` ——线程模型/锁纪律（写锁非重入，全库已防嵌套）

## 7. 已知弱点（详见 architecture.md §6）

架构：单机单进程无水平扩展 ｜ 前端全局 state ｜ 轮转双轨
安全：无自动化安全测试 ｜ 无显式 CSRF token ｜ rate limit 仅登录
数据：去重三套口径 ｜ 旧 parse_runs 累积
运维：无指标导出 ｜ Fernet 换机风险 ｜ 备份恢复未演练
